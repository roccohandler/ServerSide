# Proof collection — the process that turns projects into evidence

**Internal.** The site currently has no testimonials, case studies or outcome data, says
so honestly, and must never fabricate any. This file is the process that fixes that the
only legitimate way: by collecting real evidence from real projects, with permission,
starting with founding client #1. The founding discount's entire justification is this
file being used.

---

## Per client — BEFORE the build starts

Capture and file (one folder per client):

- [ ] Full-page screenshots of the existing site: home, top service pages, contact —
      desktop and mobile
- [ ] Traffic: sessions/month (from their analytics if any exist; note "none" honestly)
- [ ] Conversion events: tracked calls, form submissions (usually "not measured" — that
      absence is itself the before-state; record it)
- [ ] Phone-click and quote-request counts where anything measures them
- [ ] Their own description of the problem, in their words (from the assessment/audit)
- [ ] Date range of the data

## Per client — AFTER launch (same yardsticks)

- [ ] Full-page screenshots of the new site, same pages, desktop and mobile
- [ ] Sessions/month over a comparable period
- [ ] Tracked calls and quote requests (now measurable — tracking is part of the build)
- [ ] What was changed and why (the Website Conversion Blueprint is this document)
- [ ] Date range, stated beside every number — never compare unlike periods silently

## Permissions (written, per client, before publishing anything)

- [ ] Case-study permission (founding clients grant this as the discount's condition —
      confirm it was actually signed, not assumed)
- [ ] Which figures may be shared, if any (client chooses; "no figures" is fine)
- [ ] Before/after screenshots approved
- [ ] Testimonial: the client's actual words, name, business and town — never
      paraphrased into something they did not say
- [ ] Written approval of the final case-study draft before it goes live

## Publishing rules

- A testimonial goes into `client/src/content/testimonials.ts` only with quote, author,
  business and location all real — the existing test enforces full attribution.
- A case study replaces a demonstration in the portfolio (`isDemo: false`); the trust
  disclosure ("this is a new business…") comes down only when real work is on the page.
- Numbers are published only with the client's written consent, with their date ranges,
  and never extrapolated ("their calls doubled" requires their data showing exactly
  that, over stated dates, with tracking that existed on both sides).
- No composite clients, no "results typical", no borrowed benchmarks presented as
  client outcomes.

## Why this matters commercially

Perceived likelihood is the weakest term in this offer's value equation and the only
one that cannot be fixed with copy. Every completed project that follows this checklist
converts fulfilment into the proof the next sale needs — and eventually into the
evidence base `docs/future-performance-guarantee.md` requires.
